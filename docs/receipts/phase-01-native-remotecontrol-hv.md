## Source failures

1. **01B and 01C. A property notification can roll back a live ViewModel revision.** `src/RetroIde.Workbench/WorkbenchViewModel.cs`, `Update`, calls `OnPropertyChanging` before assigning either field. `WorkbenchController.RefreshViews` invokes it synchronously from `DockLayout.Publish`. A one-shot `PropertyChanging` observer that focuses Output during publication of Registers can complete the nested update to revision 2. The outer update then writes Registers at revision 1 back into the ViewModel. `WorkbenchUnitOfWork.Execute` reads that ViewModel address for its revision guard and captures that same source for its result. It can therefore publish a context older than the live Dock state and accept a revision that should be stale. The supplied atomic-notification assertion checks the paired values in a regular `PropertyChanged` callback. Its focus-change callback uses `Dispatcher.Post`, which avoids this reentrant sequence.

2. **01C. A live query can emit a workspace identity its own schema rejects.** `src/RetroIde.Workbench/WorkbenchSession.cs`, the public constructor, accepts `Guid.Empty` and passes it to the workspace, ViewModel and matching controller. `WorkbenchController.Register` checks equality with its workspace, so the empty value registers successfully. `src/RetroIde.Application/ViewContextContract.cs`, `Capture`, emits it, while `Schema` excludes it and `TryRead` rejects it. The desktop startup path uses `Guid.NewGuid()`. The defect is reachable through the public composition path, and the existing test covers rejection of submitted data without testing this source of invalid snapshots.

3. **01D. Main-window close can save before orphan recovery runs.** `src/RetroIde.Workbench/DockLayout.cs` posts `RestoreLostPanes` at `Background` priority when a float closes. `src/RetroIde.Workbench/WorkbenchWindow.cs`, `SaveLayoutAndCloseAsync`, captures synchronously at the start of main-window close. If the closed float has left `Root.Windows` and recovery is still queued, capture can omit its tools. The save then writes that snapshot, and `DockLayout.Compatible` rejects it next time because the saved pane IDs are incomplete. The orphan test waits for the background dispatch before inspecting the recovered layout. That proves the recovery after it runs and leaves the close-ordering case exposed.

4. **01A, 01C and 01D. The compiled trace can pass with unlinked public contracts.** `eng/Verify-Phase01Trace.ps1` discovers annotated test methods dynamically, then checks only its fixed `$contracts` list. The public request, response, address and layout types above have no criterion annotations and fall outside that list. The supplied 12-contract result is valid for the configured list. The Linux receipts against the compact projection and the effective export resolve the earlier missing-input finding. They leave this enforcement gap.
