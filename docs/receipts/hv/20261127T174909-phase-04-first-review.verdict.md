## Findings and regressions

1. **04A and regression in `EXEC-TODO-003` — MCP changes do not refresh the open Emulators pane.** `emulator_select_bundle`, rollback, and removal complete through the shared CQRS path. The package handlers return their results to MCP, but that path has no publication to the registered Emulators view. The pane assigns `ActivePin` and `ActiveBinding` in `LoadProjectAsync`, reached from its own reload, project selection, or successful pane command. A client can select a different package while the pane is open and immediately read the new pin through MCP while the pane retains the old selection. The pane fixture clicks **Select** in the desktop and reads the result through MCP. The two-transport package test checks persisted state and lease behavior without asserting a rendered update after an MCP command. This regresses the accepted MCP/UI parity contract for an affected view. Anchors: `WorkbenchDispatch.cs:233,447–463`, `EmulatorFeatures.Packages.cs:30–57`, `EmulatorsViewModel.cs:126–170`, `EmulatorBundleIntegrationTests.Pane.cs:46–80`, `EmulatorBundleIntegrationTests.PackageTools.cs:18–57`. Requirements: `FR-RETRO-015#ac-mcp-ui-parity`, `TR-RETRO-MCP-015#ac-mcp-typed-dispatch`, `TEST-RETRO-015#ac-test-mcp-same-instance`.

2. **04B — A reconciled operation ID loses its payload binding after another reconciliation.** The coordinator stores one `_lastResolution` and compares the incoming payload only against that record. Take an uncertain operation A confirmed `NotApplied`, then an uncertain operation B also confirmed `NotApplied` at the same state revision. B replaces A. A subsequent request using A’s original scope and a changed payload reaches normal dispatch. The fixture’s host checks actor and expected revision and does not maintain an operation-ID history, so those checks do not catch this case. The contract also assigns same-instance deduplication to hosts, but the retained fixture does not prove that protection across reconciliation or reattachment. Anchors: `EmulatorSessionControl.cs:14–15`, `EmulatorSessionControl.Mutations.cs:37–53,99–123`, `AdapterConformanceTests.Fixture.cs:69–95`, `AdapterConformanceTests.Control.cs:46–92`. Requirements: `TR-RETRO-ADAPTER-010#ac-operation-results`, `TEST-RETRO-010#ac-test-control-semantics`.

3. **04B — A late state reply can use superseded capabilities and revisions.** `ReadAsync` compares the reply with the state captured before awaiting the adapter. If a newer event arrives during the await, `Publish` correctly keeps the newer state, but `ReadAsync` still returns the older reply. The typed query and mutation gates use that reply for capability and expected-revision checks. The host can still deny the call. The coordinator nevertheless forwards a request its current state would reject. The retained gap tests cover serial refresh and resubscription. Anchors: `EmulatorSessionControl.cs:28–42,59–82`, `EmulatorSessionControl.Queries.cs:16–29`, `EmulatorSessionControl.Mutations.cs:55–73`, `AdapterConformanceTests.Events.cs:13–35`. Requirements: `FR-RETRO-010#ac-capability-ui`, `TR-RETRO-ADAPTER-010#ac-operation-results`.

4. **04C — The machine watch misses a change in descriptor availability.** `WatchMachineAsync` refreshes after a gap, a map event, or a lifecycle change. A valid `SessionStateChanged` that withdraws or restores `retroide.machine-descriptor` while the lifecycle stays `Connected` produces no descriptor update. An explicit describe call reflects the new capability, and advertised raw inspection remains independently callable. An existing watch can nevertheless leave its consumer with the last descriptor or the last unavailable result. Anchors: `EmulatorSessionControl.Machine.cs:13–65`, `EmulatorSessionControl.Events.cs:88–94`, `MachineDescriptorConformanceTests.cs:45–75`, `MachineDescriptorCompatibilityTests.cs:18–36`. Requirements: `FR-RETRO-017#ac-machine-description-discovery`, `FR-RETRO-017#ac-machine-description-legacy`, `TR-RETRO-MACHINE-017#ac-descriptor-revision`.
