## Remaining findings

1. **04A and `EXEC-TODO-003` — A project switch can strand the previous project’s package details.** With two projects open, let a successful MCP mutation start a passive refresh while project A is selected. Switch the enabled picker to B while the refresh awaits A’s selection. `OnSelectedProjectChanged` skips the read because `IsBusy` is true. `LoadProjectAsync` then discards A’s reply because the selected project changed. The switch never sets `_reloadRequested`, so the pass can finish with B selected and A’s pin, binding, profile and rollback history still shown. Success-only publication, registration checks and coalescing of package notifications work on their covered paths. The rendered transport test holds one project selected throughout. `EmulatorsViewModel.cs:54–58,142–189,212–244`, `EmulatorsPane.cs:90–109,150–156`, `DockPaneControls.cs:62–83`, `EmulatorBundleIntegrationTests.Pane.cs:103–156`.

2. **04B and 04C — Mapped operations can dispatch after their state check has been superseded.** The original late-`GetStateAsync` case is fixed. A mapped write still checks revision and capability, then awaits a separate descriptor request. During that await, a valid event can advance the state revision or withdraw mapped writes while leaving the descriptor and map revision valid. The coordinator proceeds to the captured memory port without rechecking the newer state. The query path has the same ordering for mapped reads. Host enforcement can reject the request, while the coordinator has already forwarded it. `EmulatorSessionControl.cs:33–50,67–81`, `EmulatorSessionControl.Mutations.cs:52–72`, `EmulatorSessionControl.Queries.cs:16–29`, `EmulatorSessionControl.Machine.cs:96–109,128–150`.

3. **04B — Pinned disposal signals cancellation while subscription cleanup can remain pending.** The new test disposes the session while both `MoveNextAsync` calls are pending, then awaits them before checking release. A consumer can instead pause after receiving an event or frame. Pinned disposal cancels the lifetime, disposes the connection and releases the lease. The suspended control iterator’s cleanup and the media source’s `DisposeAsync` still depend on the consumer advancing or disposing its iterator. Media cancellation can stop the pump while leaving the source undisposed. The retained fixture’s connection disposal only sets a flag, so it supplies no secondary cleanup. `PinnedEmulatorSession.cs:44–64`, `EmulatorSessionControl.Events.cs:25–33,70–99`, `EmulatorSessionControl.Media.cs:39–70`, `EmulatorBundleIntegrationTests.Attachments.cs:54–90,210–240`.

4. **04C — The initial descriptor result and the watch’s comparison state can come from different snapshots.** Start a descriptor watch while the port is advertised and hold the first descriptor reply. Let another reader publish a valid withdrawal while the session stays connected. Release the descriptor reply with the same map revision. The watch yields the descriptor and records the already-withdrawn state as `previous`. When the watch receives the withdrawal from its original cursor, it sees no availability change and emits no unavailable result. The retained test withdraws and restores capability after the first result has been delivered. `EmulatorSessionControl.Machine.cs:13–25,27–83`, `EmulatorSessionControl.Events.cs:90–96`, `MachineDescriptorConformanceTests.cs:81–110`.
