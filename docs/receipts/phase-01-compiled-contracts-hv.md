## Source findings that keep the tasks open

1. **FAIL · 01B and 01C · Reentrant focus can return `ok` with another tool’s context.** In `DockLayout.cs`, `Focus` checks the target before `Publish`, which synchronously invokes `Changed`. The current reentrancy test in `WorkbenchDispatchTests.cs` proves that a `PropertyChanging` observer can focus Output during an outer Registers focus. The repair in `WorkbenchViewModel.Update` correctly keeps the newer pair at revision 2. The outer `Focus("registers")` still returns `true`, and `WorkbenchUnitOfWork.Execute` in `WorkbenchDispatch.cs` then captures Output at revision 2 for the Registers operation. This affects both UI and MCP. The focused red/green test establishes monotonic publication. It does not assert the command’s returned context in that scenario.

2. **FAIL · 01C · The public typed address loses a required field when the selection is null.** In `ViewContextContract.cs`, `WireJson.Options` omits null properties. Serializing a new workbench’s `WorkbenchAddress` with those public options omits `activeToolId`. `TryRead` requires all four fields and rejects that representation, while discovery advertises the field as required and nullable. The captured JSON from `workbench_get_context` retains the explicit null and works. `ProductionAttachmentTests.CallFocusAsync` also explicitly includes the nullable field in its wire object. Those passing paths leave the typed serialization mismatch uncovered.

3. **FAIL · 01D · Closing an accepted float can drop its documents from the next save.** In `DockLayout.cs`, `Compatible` and `Build` accept a floating `document-tabs` branch containing a shell document. Moving Emulation from the main branch into such a saved branch preserves the required set of IDs and passes validation. Once that float closes, `RestoreLostPanes` only visits `_tools`. The next capture omits the lost document and the next restore rejects the layout because an expected ID is missing. The current orphan recovery test floats six tools and keeps every document in the main host.

4. **FAIL · 01D · Floating Dock controls remain available while the closing layout snapshot is written.** `WorkbenchWindow.SaveLayoutAndCloseAsync` captures the topology before starting the asynchronous save. `BuildSurface` installs the workbench-wide block around the main `DockControl`. Floating hosts receive overlays on their pane content through `WorkbenchApp.Initialize`, and their Dock tab and window controls are outside those overlays. Consequently a float can close or its layout can change after capture while the main close save is pending. The synchronous recovery repair handles a float already closed at capture time. It leaves this later interval open.

5. **FAIL · Shared trace, including A6/C10/D9 · The compiled verifier accepts some links that do not identify runnable tests.** In `eng/Verify-Phase01Trace.ps1`, the managed test lookup drops parameter signatures from XML IDs and emits only type plus method name from assembly metadata. An annotated ordinary overload can therefore borrow the identity of a runnable overload. Test attributes are checked by type name alone, so an explicitly skipped fact can satisfy a criterion link. Native names are a hard-coded list without a compiled method or entry-point reachability check, and the public type walk sees top-level `Public` types only. The reported 38 links and 32 contracts are valid results of the current check. They establish the narrower metadata checks the script actually performs.
