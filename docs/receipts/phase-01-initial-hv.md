# BDPv4 hostile validation receipt: Retro IDE Phase 01

`OverallVerdict: DISAGREE`

`ValidatorIdentity: ChatGPT-6.2-SOL-HIGH-LEGION2`

The frozen snapshot and captured runs support a real Avalonia/Dock workbench, one shared focus command, and a common typed handler reached by UI, stdio, and Streamable HTTP. Phase 01 remains open because an accepted layout can fail during startup, scoped operations can block the UI dispatcher, and several acceptance claims exceed what the supplied tests and receipts establish.

## Blocking findings and remediation

1. **A saved layout can pass compatibility checks and fail during restore.** In `src/RetroIde.Workbench/DockLayout.cs`, `Compatible` accepts a main document group with pinned tools and the remaining tools in floating groups. That layout can contain all required pane IDs exactly once. The constructor calls `RestorePinned` before it builds the floating layouts. If the main root contains no `IToolDock`, all three owner lookups fail and the final `.First()` throws. Make compatibility checks and owner resolution agree. Add a regression that loads this topology through `LayoutStore` and verifies a successful restore or a safe fallback.

2. **The scoped wait API can block the dispatcher it is meant to keep responsive.** In `src/RetroIde.Workbench/InteractionBlocks.cs`, `RunAsync` invokes `operation(cancellationToken)` inline when entered on the UI thread. A delegate that performs synchronous work before returning its task keeps the dispatcher occupied. `ConfigureAwait(false)` only affects the continuation. The tests use delegates that return pending tasks immediately, and the snapshot has no production caller of `RunAsync`. Establish and enforce how work leaves the dispatcher, then exercise that path from a workbench operation. In `tests/RetroIde.NativeTests/NativeDockingTests.cs`, `VerifyWaitAsync` checks an Avalonia cursor property on any visible border and finds pane content by text shared with other panes. Bind the assertion to Registers, move the pointer over its blocked surface, and verify the effective platform cursor and restoration.

3. **The layout test proves survival of an independent worker, with workbench-associated session preservation still open.** In `tests/RetroIde.IntegrationTests/ShellLifecycleTests.cs`, `RunningAdapterFixture` answers every query with the same immutable `SessionState`. The workbench has no connection to the fixture. The test proves that the worker still answers across close and reopen and that its ID is absent from the saved JSON. A Phase 01 deterministic fixture can close the remaining gap by representing the workspace’s running session, exposing lifecycle calls or mutable state, and proving that restore sends no stop, restart, or reset.

4. **Selected-instance evidence stops short of two running desktop processes.** `Http_stdio_and_ui_focus_the_same_live_dockable` starts two sessions and two loopback hosts in one test process. The second session has no window. The native executable uses `SetupWithoutStarting()` and constructs its own workbench window, so it bypasses the production lifetime and attachment startup in `src/RetroIde.Workbench/Program.cs` and `WorkbenchApp.cs`. The earlier focus-parity summary covers one live workbench. Exercise two production workbench processes, attach both clients to the chosen process, verify the other process stays unchanged, and verify open clients lose access on revocation or shutdown.

5. **Trace and negative-control output does not establish the full BDPv4 gate.** `eng/Verify-Phase01Trace.ps1` checks a fixed manifest of 14 test entries and nine documented types. QBrain criterion validation depends on a nonempty optional export, so the success line alone cannot establish that it ran. The snapshot supplies no CI invocation. The negative-control summary supplies failed test names without the applied mutations, failing assertions, or mock-green and real-entry-point red receipts. Supply the CI trace invocation and export-backed result, and retain each mutation with its expected assertion and actual failure.

The earlier negative-control run reports all three named tests failed. Without the mutation diff and assertion failures, those results cannot be attributed to particular broken behaviors.
