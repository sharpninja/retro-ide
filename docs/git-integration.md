# Git integration

The Phase 03 workbench has a Git menu and a dockable Source Control pane. A workspace can contain several repositories and linked worktrees. Choose a folder or file in Project Explorer, open **Git → Show Source Control**, and select **Use Explorer Selection**. **Refresh Status** reads the selected checkout and displays its branch and staged, working-tree, and conflicted paths. The menu and pane use the same commands. [Project Explorer](architecture.md#project-explorer)

New layouts dock Source Control beside Project Explorer. Older saved layouts get an auto-hidden Source Control tab on the left edge while keeping their existing tabs, pins, and floating windows. The rest of this page defines the Phase 03 workflows.

Use **Git → Initialize Repository** to open an existing checkout or initialize a new or existing folder. Use **Git → Clone Repository** with a Git URL or local repository path and a new or empty destination. The destination uses an absolute path with an existing parent. Both commands add and select the resulting folder in Project Explorer and Source Control after Git succeeds. [Git Init](https://git-scm.com/docs/git-init) · [Git Clone](https://git-scm.com/docs/git-clone)

Setup leaves the current root and checkout selection in place when Git fails. Cloning into an existing empty folder retains its Unix mode or Windows access control. The desktop shows Source Control’s Wait overlay while setup blocks its commands.

## Workspace and worktree context

Discover repositories for project and folder roots. Opening a nested repository or a submodule gives it its own context. A linked worktree has its own working files, index, and checked-out state and shares repository data with its sibling worktrees. The IDE saves the selected Git checkout with the workspace. It verifies the checkout again when reopening. If the saved checkout is unavailable, Git opens without a selection and the remaining roots stay browsable. [Git worktrees](https://git-scm.com/docs/git-worktree)

Project Explorer shows tracked, untracked, ignored, modified, staged, and conflicted badges for the selected worktree’s authorized directory. External changes to the worktree, its index, or its refs refresh Explorer and Source Control automatically. **Refresh Status** and the attached MCP status tool can also request a refresh. Selecting another checkout clears the previous badges. A file with both staged and working-tree changes shows both labels. If the selected checkout becomes unavailable, the IDE clears its status and refreshes it when it returns. [Git status](https://git-scm.com/docs/git-status#_porcelain_format_version_2) · [Git index paths](https://git-scm.com/docs/git-ls-files)

Select a file under **Working tree changes** or **Staged changes**, then choose **Open Diff**. Double-clicking a file opens the same view. Each layer has its own read-only editor tab, which shows the full path and checkout. Reopening a layer refreshes its existing tab. The Git menu and Source Control command bar also offer **Stage File** and **Unstage File** for the current selection.

In a text diff, select one or more hunks and choose **Stage Selected Hunks** or **Unstage Selected Hunks**. The tab refreshes after a successful operation. If the file or index changed since you opened the patch, choose **Refresh Diff** and select the hunks again. Use the whole-file commands for binary changes, file additions and deletions, renames, and mode changes. [Git apply](https://git-scm.com/docs/git-apply)

The working-tree diff compares files against the index and the staged diff compares the index against HEAD. Unstaging preserves the working copy. Each index update is prepared privately and published only while holding Git’s index lock and after verifying the index still matches its starting state. [Git diff](https://git-scm.com/docs/git-diff) · [Path-specific Git reset](https://git-scm.com/docs/git-reset) · [MCP tools](mcp-tools.md#phase-03-git-tools-in-development)

Open the worktree root and choose **Commit Staged Changes** or **Amend Last Commit** from the Git menu or Source Control. The dialog shows the checkout and branch. Amend preloads the last message. Git writes the reviewed index, leaves unstaged edits in the working tree, and runs the configured hooks and signing program. If HEAD or the index changed while the dialog was open, review the new staged state before retrying. [Git commit](https://git-scm.com/docs/git-commit) · [Git hooks](https://git-scm.com/docs/githooks)

Open **Git History** from the Git menu or Source Control. The tab starts at the selected worktree’s HEAD and lists local branches, remote refs, tags, and linked worktrees. Choose a ref to follow its history. **Newer** and **Older** move through pages pinned to the starting commit. Select a commit to see its author, message, and changed files. The graph shows each merge parent. The changed-file list compares the merge to its first parent. [Git log](https://git-scm.com/docs/git-log) · [Git refs](https://git-scm.com/docs/git-for-each-ref) · [Git worktrees](https://git-scm.com/docs/git-worktree)

Select a file in Project Explorer or Source Control and choose **Open Blame** from the Git menu or Source Control. The read-only tab shows line attribution for the selected checkout’s working file. Select a line for its originating path, full commit ID, and summary. Git traces renamed lines back to their earlier path and identifies uncommitted disk changes. Open editor drafts remain separate from the file on disk. Use **Refresh Blame** after a change on disk. [Git blame](https://git-scm.com/docs/git-blame)

Select a commit in Git History and choose **New Tag**. Enter a name and an optional annotated message. Git applies your configured signing behavior. Select the tag in the refs list and choose **Inspect Tag** to see its object ID, target, tagger, and annotation. **Delete Tag** asks you to review the tag and then checks its object ID again inside Git's ref update. Tags are shared by the repository’s linked worktrees. [Git tag](https://git-scm.com/docs/git-tag) · [Git update-ref](https://git-scm.com/docs/git-update-ref)

Use the **Worktrees** section in Git History to refresh the repository’s checkouts and see which checkout is primary, locked, or missing. **Add Worktree** takes a destination and the selected commit. Enter a new branch name, use a local branch selected in the refs list, or leave the branch field empty for a detached checkout. **Open Worktree** opens the folder in Project Explorer and switches Source Control and Git History to it. **Lock Worktree** accepts an optional reason. Unlock the checkout before removing it.

To remove a checkout, select it from another checkout’s Git History and review its path, branch, and HEAD. Removal closes its clean source tabs and removes its Explorer roots. Save or move local changes and ignored files first and finish any active Git operation. The branch and commits stay in the repository. [Git worktree](https://git-scm.com/docs/git-worktree)

Choose **New Branch** to create a local branch from the selected commit in Git History. With no commit selected, the dialog uses the current history anchor. Select **Switch to the new branch** to check it out as part of creation. Choose a local branch and **Switch Branch** to check it out. Git rejects a switch that would overwrite local files or take a branch checked out elsewhere. Save affected unsaved editor buffers before switching. Retro IDE reloads affected clean tabs after a successful switch. [Git branch](https://git-scm.com/docs/git-branch) · [Git switch](https://git-scm.com/docs/git-switch)

Choose **Rename Branch** to move the local branch and keep its tracking configuration and reflog. A branch checked out in another worktree must be renamed from that checkout. **Delete Merged Branch** confirms the exact branch name and asks Git to delete it only when it is fully merged into its upstream or, without an upstream, the current HEAD. A checked-out branch cannot be deleted. [Git branch](https://git-scm.com/docs/git-branch)

Open **Remotes** from Git History to add, rename, remove, or edit a remote. The URL field accepts a Git URL or local repository path. Select **Set push URL** to edit the push endpoint. Retro IDE masks embedded credentials in existing URLs. Use Git’s credential helpers or SSH credentials for authentication. Choose a remote and **Fetch** to update its tracking refs and Git’s ahead and behind counts. The checked-out branch and its files stay in place. Use **Set Upstream** on a local branch to choose or clear tracking. [Git remote](https://git-scm.com/docs/git-remote) · [Git fetch](https://git-scm.com/docs/git-fetch) · [Git credentials](https://git-scm.com/docs/gitcredentials)

In **Remotes**, pick the remote and enter the destination branch. **Push** sends the displayed local branch tip. To replace divergent history, select **Force push with lease** and enter the full remote commit ID you reviewed. Git rejects the update if that remote branch moved. **Pull** integrates the selected remote branch into the displayed checked-out branch. It defaults to **Fast-forward only** and also supports **Merge** and **Rebase**. Save or discard affected unsaved editor changes before pulling. A successful pull refreshes affected clean editor buffers. Git reports integration conflicts in the current worktree. [Git push](https://git-scm.com/docs/git-push) · [Git pull](https://git-scm.com/docs/git-pull)

## Start or recover an operation

Select a commit in **Git History** and choose **Apply Commit**. Review the checkout, its current HEAD, and the full ID of the selected commit. Choose **Merge**, **Rebase onto commit**, **Cherry-pick**, or **Revert**. When cherry-picking or reverting a merge commit, choose which parent Git should treat as the mainline. Retro IDE checks the reviewed HEAD and branch before starting. If Git pauses, open **Source Control** to resolve or abort the operation.

Source Control shows when the selected worktree has a paused merge, rebase, cherry-pick, or revert. Resolve the paths under **Conflicts** and stage the resolutions to enable **Continue Git Operation**. Git uses the operation’s prepared commit message and runs its configured hooks. **Abort Git Operation** asks you to confirm the affected worktree before Git restores its earlier state. Save or discard open editor changes in that worktree before either action. Retro IDE rechecks the operation’s reviewed index and working changes before invoking Git. [Git merge](https://git-scm.com/docs/git-merge) · [Git rebase](https://git-scm.com/docs/git-rebase) · [Git cherry-pick](https://git-scm.com/docs/git-cherry-pick) · [Git revert](https://git-scm.com/docs/git-revert)

**Skip Current Commit** lets you review and omit the paused commit in a rebase, cherry-pick, or revert. Git resumes the remaining sequence and may pause at the next conflict. [Git rebase](https://git-scm.com/docs/git-rebase) · [Git cherry-pick](https://git-scm.com/docs/git-cherry-pick) · [Git revert](https://git-scm.com/docs/git-revert)

## Reset a checkout

Select a commit in **Git History** and choose **Reset to Commit**. **Soft** moves HEAD and keeps the index and files. **Mixed** also resets the index and keeps working files. **Hard** also replaces tracked files with the selected commit. The dialog shows the index and tracked paths affected by the selected mode. An affected unsaved editor buffer or an untracked or ignored file in the way blocks a hard reset. Retro IDE rechecks the reviewed HEAD, index, and disk contents before applying the chosen mode. [Git reset](https://git-scm.com/docs/git-reset)

## Stash checkout changes

Open **Stashes** from Source Control. Enter a message and choose whether to include untracked files. Select a stash to inspect its patch and optionally restore staged changes when applying it. **Apply** keeps the entry. **Pop** applies it and removes the reviewed entry after success. A conflict keeps the entry and reports the paths to resolve. **Drop** removes the selected entry from the shared stash stack. Refresh the list if another checkout changed the stack. [Git stash](https://git-scm.com/docs/git-stash)

## Export or apply a patch

Open **Patches** from Source Control and choose **Index** for staged changes or **Worktree** for tracked working changes. **Export Patch** saves native Git patch bytes, including binary changes. **Open and Review** checks an existing patch against the selected layer and lists the affected paths. **Apply Patch** updates that layer. A worktree apply refreshes affected clean editors and stops if they contain unsaved changes. Review again after changing the destination or if the checkout has changed. [Git diff](https://git-scm.com/docs/git-diff) · [Git apply](https://git-scm.com/docs/git-apply)

## Workflows

| Area | IDE commands and views |
| --- | --- |
| Repositories and configuration | Clone, Init, open existing repositories, select a repository or worktree, inspect and edit remotes and upstream tracking, expose ignored files and edit ignore rules. Show authentication or repository errors with the affected context. |
| Changes and index | Review working-tree and staged diffs, including renames and binary changes. Stage and unstage selected files or hunks. Restore selected content and distinguish index changes from working-file changes. |
| Commits and history | Commit staged changes, amend, inspect commit graph and details, review file history and blame, compare refs or commits, and create or inspect tags. Git applies configured hooks and signing. |
| Branches and remote communication | Create, switch, rename, and remove branches. Fetch, pull with the selected integration strategy, push, set an upstream, and report rejected updates or divergence. Force-with-lease is an explicit push variant. |
| Integration and recovery | Merge, rebase, cherry-pick, revert, and reset with explicit target and mode. Display the current operation and offer the actions Git allows, such as Continue, Skip, or Abort. Resolve file conflicts in a merge editor and stage the resolved file. |
| Stashes and patches | Create, inspect, apply, pop, and drop stashes. Apply or export patches with the selected index or worktree destination. |
| Worktrees, submodules, and LFS | List, add, open, lock, unlock, and remove linked worktrees. Show submodule status and support init, update, and sync in the selected repository. Honor configured Git LFS filters and hooks and expose LFS commands where Git LFS is installed. |
| Advanced commands | Open the integrated terminal in the selected worktree with the same native Git environment. It supports arbitrary Git commands and extensions, including reflog, bisect, notes, and recovery workflows. Refresh IDE state after terminal and external client changes. |

## Execution and state

Use the installed Git executable for repository operations on Windows and Linux. The IDE discovers Git or accepts a configured executable and reports its availability. The Source Control ViewModel registers with the main controller. Commands launch typed CQRS requests with the repository, worktree, and selected files or refs captured at invocation. The Git service invokes the executable asynchronously with explicit arguments and working directory. Its interactive commands use the user's Git configuration, HTTPS credential helpers, SSH agent, and signing environment. Credential prompts and signing tools use their interactive channels, and logs omit secrets. [Git credentials](https://git-scm.com/docs/gitcredentials)

- Read repository status from stable machine output such as `git status --porcelain=v2 -z --branch`. Parse NUL-delimited paths and change records. Pass literal paths or use NUL-delimited pathspec input where Git supports it. Resolve the worktree Git directory and common Git directory through Git so linked worktrees use the right context. [Git status porcelain format](https://git-scm.com/docs/git-status#_porcelain_format_version_2)
- Use Git and the filesystem as the source of truth. Refresh after a command and when relevant files, the index, or refs change outside the IDE. Coalesce duplicate refresh requests and apply results to their captured context. Preserve native Git locks and serialize overlapping IDE writes to the same index, working files, or shared refs.
- Capture the relevant staged or working content for hunk operations. Recheck it before applying a selected hunk and refresh the diff if it changed. Treat the working file, open editor buffer, and index as distinct states. Show external changes to a dirty editor so the user can reconcile them before replacing their edits.
- Detect ongoing operations started in the IDE or an external client. The merge editor maps Git's base and conflict stages to the specific merge, rebase, or cherry-pick. Selecting a resolution edits the file. Staging records the resolved file, and the operation's Continue or Abort command follows native Git behavior.
- Return structured outcomes with the command, repository context, exit status, and relevant Git diagnostics. Refresh state after errors and cancellation before enabling follow-up actions. When an operation logically blocks interaction in a scope, display the workbench's system wait cursor over that scope.
